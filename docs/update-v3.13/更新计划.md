# Karma v3.13 更新记录

## 上下文

本次更新基于 v3.12 之后的三个问题与两个视觉需求：

1. **设置页阶位增删闪退**（严重）：正/负阶位体系页里「加/减阶位」会闪退，logcat 定位到 `SettingsViewModel.addNegativeRankAfter` 的 `IndexOutOfBoundsException`。
2. **导出覆盖已有文件时 JSON 损坏**：本应导出的完整 JSON 末尾被追加一段不完整的旧内容残尾。
3. **衰减开关误写未保存草稿**（隐患）：打开「启用衰减」会把整个未保存的设置草稿写进数据库。
4. **数轴视觉优化**：阶位色块 30%/70% 处「微微更亮」（马赫带错觉）；数轴长条上下两端需要虚化；左侧分数数轴未与上方数字对齐。

所有修改均已通过 `:app:compileDebugKotlin` 编译验证。

**涉及文件：**
- `ui/settings/SettingsViewModel.kt`（阶位增删越界修复 + 衰减开关误写草稿修复）
- `data/repository/KarmaRepository.kt`（新增 `updateDecayFields`）
- `ui/history/HistoryViewModel.kt`（导出显式截断）
- `ui/main/components/AxisCanvas.kt`（smoothstep 渐变 + 上下虚化）
- `ui/main/components/ScorePanel.kt`（分数数轴居中）
- `build.gradle.kts`（版本 3.12 → 3.13，versionCode 20 → 21）

## 1. 修复设置页阶位增删越界闪退

### 现象

设置页「正阶位体系 / 负阶位体系」中，在**最后一个阶位**上点 `+`（加阶位）立即闪退；正、负阶位均复现。

### logcat 堆栈

```
java.lang.IndexOutOfBoundsException: Index: 9, Size: 8
    at java.util.ArrayList.add(ArrayList.java:483)
    at com.example.karma.ui.settings.SettingsViewModel.addNegativeRankAfter(SettingsViewModel.kt:442)
```

### 根因

`addRankAfter` / `addNegativeRankAfter` 的 else 分支（在最后一个阶位下方插入时）执行：

```kotlin
newThresholds.add(insertPos, prev ± 10/50f)
```

其中 `insertPos = index + 1 = 阶位数`（index 是最后一个阶位的下标），而阈值列表只有 `阶位数 - 1` 个元素。`ArrayList.add(index, element)` 在 `index > size` 时抛 `IndexOutOfBoundsException`。

- 用户数据：负阶 9 个（thresholds 8 个）→ 最后一个负阶上点 `+` → `add(9, ...)` 于 size=8 → 崩溃（即 logcat 的 `Index: 9, Size: 8`）。
- 正阶同理：12 个正阶（thresholds 11 个）→ `add(12, ...)` 于 size=11 → 崩溃。
- 中间插入不受影响（`insertPos < thresholds.size` 分支），所以此前用户成功加过阶位。

### 修改（`SettingsViewModel.kt`）

- `addRankAfter` else 分支：`newThresholds.add(insertPos, prev + 50f)` → `newThresholds.add(prev + 50f)`（纯追加，新边界永远在列表末尾）。
- `addNegativeRankAfter` else 分支：`newThresholds.add(insertPos, prev - 10f)` → `newThresholds.add(prev - 10f)`。
- 顺手防护：`deleteRank` / `deleteNegativeRank` 增加 `index !in ...indices` 越界检查——快速连点删除时 UI 索引尚未重组、可能过期，`removeAt` 同样会越界，直接忽略。

## 2. 修复衰减开关误写整个未保存草稿

### 隐患

`updateDecayEnabled(true)` 原来执行 `repository.updateAllSettings(_draft.value)`——把**整个未保存的设置草稿**（阶位增删、事件编辑等）直接写入数据库，即使没点「保存设置」。且 `original` 快照未同步，保存按钮状态会失真。

### 修改

- `KarmaRepository.kt`：新增 `updateDecayFields(decayEnabled, lastDecayDate)`——按既有部分更新模式（读 DB 当前行 → `copy` 只改衰减两个字段 → upsert），完全不碰草稿和其他设置列。
- `SettingsViewModel.kt`：`updateDecayEnabled` 协程改用 `repository.updateDecayFields(decayEnabled = true, lastDecayDate = today)`，之后照旧执行 `applyDecay()` 并把结果（totalScore / lastDecayDate）同步回草稿。行为不变：打开开关仍立即执行一次衰减检查。

## 3. 修复导出覆盖已有文件时旧内容残留导致 JSON 损坏

### 现象

导出 JSON 时，若选择**覆盖一个已有文件**，导出的文件格式错误：本应导出的完整 JSON 末尾被追加了一段不完整的旧内容残尾。

（这也是 v3.12 之前 `karma_data.json` 损坏——「2000 条完整记录 + 88 条残尾」——的真正原因；v3.12 的 `exportInProgress` + `NonCancellable` 只解决了并发/中断写，没解决覆盖不截断。）

### 根因

`HistoryViewModel.exportJson` 写盘用的是单参 `contentResolver.openOutputStream(uri)`（默认模式 `"w"`）。`"w"` 是否截断取决于 ContentProvider 对模式字符串的解释：标准 ExternalStorageProvider 会带 `TRUNCATE`，但部分厂商（如华为）的 Provider 对 `"w"` 不截断——流从文件头位置 0 写入、旧文件未清空。新 JSON 比旧文件短时，旧文件超出新 JSON 长度的尾部残留 → `[本次完整导出] + [旧内容残尾]`。

### 修改（`HistoryViewModel.kt`）

`openOutputStream(uri)` → `openOutputStream(uri, "rwt")`。`"rwt"` 是 `ContentResolver.openOutputStream` 文档中唯一带显式截断语义的模式（`ParcelFileDescriptor.parseMode("rwt")` = `READ_WRITE|CREATE|TRUNCATE`），强制 O_TRUNC，不再依赖厂商对 `"w"` 的实现。

## 4. 数轴阶位色块渐变改 smoothstep（消除马赫带）

### 现象

主屏中间数轴的阶位色块，在左右渐变 30%/70% 附近看起来「微微更亮」。

### 原因

色块横向渐变原为线性 4 点：`0→30%` 线性升 alpha、`30%~70%` 实色、`70%~100%` 线性降 alpha。线性渐变的 alpha 曲线在 30%/70% 拐点处**斜率突变**，人眼侧抑制会把突变处放大成隐约亮带（马赫带错觉）。

### 修改（`AxisCanvas.kt`）

- 新增 `BAND_RAMP`：左右渐变段各 8 个 smoothstep 采样点（`t²(3−2t)`，端点导数为 0），中间 0.3~0.7 靠相邻 stop 插值保持恒 1（实色不变）。
- 色块绘制改为 `BAND_RAMP.map { pos to rankColor.copy(alpha = alpha) }` 展开为 vararg（该 Compose 版本无 `List<Pair>` 重载，需 `*...toTypedArray()`）。
- 整条 alpha 曲线导数连续，拐点不再产生亮带。

## 5. 数轴上下两端各 15% 虚化

### 需求

数轴长条（色块 + 刻度 + 标签）上下两端像左右一样渐隐：顶部/底部各虚化画布高度的 15%。

### 实现（`AxisCanvas.kt`）

二维问题（水平渐变 × 垂直虚化）用「图层 + 垂直 DstIn 蒙版」解决（即该文件最初 `vertical DstIn fade` 的设计思路）：

1. `drawIntoCanvas { canvas.saveLayer(bounds, Paint()) }`：整个数轴内容（色块 → 刻度 → 标签 → 轴线 → 光点 → 范围标签）先画进独立图层。
2. 末尾 `drawRect(brush = Brush.verticalGradient(*VERTICAL_FADE_STOPS), blendMode = BlendMode.DstIn)`：DstIn 只取蒙版 alpha，按高度整体淡出上下两端。
3. `drawContext.canvas.restore()` 合成回画布。

蒙版 `VERTICAL_FADE_STOPS`：顶部 0→15%、底部 85%→100% 各 8 个 smoothstep 采样点（透明↔不透明），中间 15%~85% 恒为不透明。只影响数轴自身图层，不影响页面背景与正中光点。

### 改 5：修复底部蒙版 stops 乱序

首版底部蒙版采样点位置是**降序**追加的（`1.0, 0.98, …, 0.85`），整个 stops 数组不递增，渐变着色器按数组顺序消费 stops → 底部虚化区从 15% 蔓延到 100%，导致下方比上方透明得多。

修复：底部改为升序构造——位置 `0.85 + 0.15×u`，alpha `1 − smoothstep(u)`。现在上下对称。

## 6. 左侧分数数轴居中

### 需求

左侧面板（`ScorePanel`）上方的「当前加减分」数字（如 `+2`）是居中显示的，但下方分数数轴竖线画在 `axisX = w * 0.35f`（左偏），没有与数字对齐。

### 修改（`ScorePanel.kt`）

`axisX = w * 0.35f` → `axisX = w * 0.5f`。数轴竖线居中，与上方居中数字垂直对齐。整数标签在轴右侧、半格标签在轴左侧，默认范围 ±6 时两侧半宽足够容纳。
