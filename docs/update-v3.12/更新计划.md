# Karma v3.12 更新记录

## 上下文

本次更新围绕三个方向：**设置页体验重构（分类化）**、**导出/导入可靠性修复**、**阶位体系拆分**。所有修改已完成并通过编译（`:app:compileDebugKotlin`）。

**涉及文件：**
- `ui/settings/SettingsScreen.kt`（设置页分类重构 + 阶位体系拆分）
- `ui/settings/SettingsViewModel.kt`（保存加固 + 负阶模式持久化）
- `ui/navigation/NavGraph.kt`（设置页过渡改淡入淡出）
- `ui/history/HistoryViewModel.kt`（导出写盘防护 + 导入错误提示）
- `data/repository/KarmaRepository.kt`（导入返回具体错误原因）
- `build.gradle.kts`（版本 3.11 → 3.12，versionCode 19 → 20）

---

## 1. 设置页分类重构

### 背景

设置页原本把所有卡片（分数区域 / 刻度区域 / 阶位设置 / 事件列表 / 每日必做 / 历史记录 / 业力衰减 / 运气增幅 / 背景渐变 / 启动经文 / 重置）从上到下罗列在一个滚动页里，项太多，一屏装不下。

### 实现（`ui/settings/SettingsScreen.kt`）

- 新增 `SettingsCategory` 枚举，7 个分类：
  - **外观与图表**：分数轴、刻度、历史图表、背景渐变
  - **正阶位体系**：正阶名称/颜色/上限/衰减/占卜次数
  - **负阶位体系**：负阶名称/颜色/下限/占卜次数
  - **事件管理**：善业/恶业/善果预设、每日必做
  - **业力机制**：业力衰减、运气增幅
  - **启动画面**：启动经文与停留时长
  - **通用**：重置所有设置为默认
- 根页只渲染 7 张分类入口卡片（标题 + 副标题 + `›` 箭头），点进分类才渲染该分类下的具体设置卡片
- 所有分类共享同一个 `SettingsViewModel`（draft/original 草稿状态），跨分类的修改一起点「保存设置」写入
- 顶栏随分类切换标题（根页「设置」/ 分类页显示分类名）；分类页内按系统返回键先回入口页（`BackHandler`），再按一次才退出设置
- 切换分类/回到入口页时滚动位置与局部编辑状态随内容重建重置（`key()`）

### 过渡动画

- `NavGraph.kt`：设置页路由从 `tween(0)` 瞬时切换改为与其他页面一致的 `fadeIn/fadeOut(tween(250, FastOutSlowInEasing))`
- 分类间切换使用 `Crossfade`（250ms 淡入淡出）
- **关键判断**：v3.10 曾因「设置页是全应用最重的页面」把设置页改为瞬间切换；v3.12 分类化后根页只有 7 张轻量卡片，进入/退出设置页组合的是轻量根页，淡入淡出不再掉帧。仍在同一分类页内的重内容（如正阶位体系的多输入框）只在进入该分类时组合一次，不再整页一次性组合

## 2. 保存机制加固（`SettingsViewModel.save`）

写库改为 `withContext(NonCancellable)` 包裹。
原因：点「保存设置」后立即 `popBackStack`，`viewModelScope` 会被取消，普通 suspend 写库可能被中断导致设置丢失。加固后保证 Room 写入完整执行。

---

## 3. 负阶增删模式持久化（`SettingsViewModel`）

`RankSettingsCard` 内负阶的 +/− 模式原为局部 `remember` 状态，分类化后切换分类会丢失（正阶模式本就在 ViewModel 里）。把 `negativeAddMode` / `negativeDeleteMode` 提升到 `SettingsViewModel`，新增 `toggleNegativeAddMode()` / `toggleNegativeDeleteMode()`，与正阶行为一致。

---

## 4. 导出/导入修复

### 背景

根目录 `karma_data.json` 损坏（格式错误、括号不匹配、重复 `version` 键）。分析发现文件 = **一份完整导出（2000 条记录，id 53→2052）+ 另一份导出被截断的残尾（88 条，id 5625→5712）** 拼接而成，是导出写盘异常（并发写/中断写）留下的损坏文件。

### 文件修复

- 保留完整自洽的主导出（2000 条，totalScore -125.0 与最后一条记录一致）
- 原损坏文件完整备份为 `karma_data_backup.json`（不丢数据）

### 导出写盘防护（`HistoryViewModel.exportJson`）

- 新增 `exportInProgress` 标志：同一时刻只允许一次导出（并发导出会互相覆盖/交错写坏文件）
- 写盘用 `withContext(NonCancellable)`：用户中途离开历史页（`viewModelScope` 被取消）也能写完整，不留下半截文件

### 导入错误提示（`KarmaRepository.importData` + `HistoryViewModel.importData`）

- `importData` 返回类型从 `Boolean` 改为 `String?`（null = 成功，非 null = 失败原因，直接展示给用户）
- JSON 解析失败 → 「JSON 格式错误，文件可能损坏或被截断：…」
- 版本不兼容 → 「JSON 格式不正确或版本不兼容（需要 version=2 的导出文件）」
- CSV → 「CSV 格式不正确」

## 5. 阶位体系拆分

「阶位体系」一个分类同时包含正阶（9 阶编辑框）+ 负阶（9 阶编辑框），是设置页最重的分类，进入卡顿。拆分为两个分类页：

- **正阶位体系**（`PositiveRankSettingsCard`）：名称/颜色/上限/业力衰减/占卜次数，+/− 增删
- **负阶位体系**（`NegativeRankSettingsCard`）：名称/颜色/下限/占卜次数，+/− 增删
- 正负阶各自独立的颜色选择器对话框（原来共用一个 + `colorPickerForNegative` 区分回写目标，现各自独立更简单）
- 增删模式状态（正阶 `addMode`/`deleteMode`、负阶 `negativeAddMode`/`negativeDeleteMode`）均在 ViewModel，拆页后切换分类不丢
