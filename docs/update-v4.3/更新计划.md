# Karma v4.3 更新计划

## 上下文

本次更新从 v4.2 出发，含 **6 项改动**，全部经用户逐条确认方案后实施：

1. **气运测试冷却**：气运测试按钮 1.5 秒内只能触发一次，冷却期间按钮变灰、颜色从左到右逐渐恢复；冷却时长可在设置中配置。
2. **计时持久化改用墙钟时间（方案 B）**：修复「过去 3 小时却只剩几秒」「有时无法计时」。
3. **左侧分数栏正数数轴变绿**：正数刻度标签由浅蓝改为绿色。
4. **加分后自动触发自证修复**：修复「加了分有时不弹被动自证」。
5. **誓约终止时间改为可选时间 + 到期判定**：终结时间改为滚轮选时间（年月日 / 时分秒，默认当前时间）；到期与业力衰减/每日必做一起判定，到期在首页弹窗询问是否完成。
6. **左侧分数栏底部新增「重置」按钮**：清空当前选中的加减分、事件、乘法按钮选中。

**版本**：`build.gradle.kts` versionName "4.2" → "4.3"，versionCode 24 → 25。
**数据库**：Room version 26 → 27（新增 1 列 + 清空旧誓约）。

## 二、计时持久化改用墙钟时间（方案 B）

### 现状问题（根因）

计时状态用 `SystemClock.elapsedRealtime()`（**本次开机以来毫秒数，重启归零**）持久化：

- `TimerState.currentElapsedMs()`：`accumulatedMs + (elapsedRealtime − resumeElapsed)`；
- `TimerService.restoreTimerState()`：`offlineMs = 当前elapsedRealtime − 保存的resumeElapsed`，仅当 `0 < offlineMs < 365天` 才回填，且**无条件把 resumeElapsed 改写为当前值**。

**设备重启后** `elapsedRealtime` 归零 → `offlineMs` 为负 → 不回填离线时长，`resumeElapsed` 又被改成小值 → 显示从 0 重新跑（用户看到「过去 3 小时只剩 7 秒」）；此状态下 `status` 仍为 RUNNING，还可能表现为「无法计时」。

### 决策表（用户确认）

| 项 | 决策 |
|---|---|
| 方案 | 方案 B：**整体改用墙钟 `System.currentTimeMillis()`**（Unix 毫秒时间戳，跨重启连续） |
| 数据库 | 不加列（沿用 `timerStartElapsed/timerResumeElapsed` 三字段，语义变为墙钟毫秒） |
| 已知副作用 | 计时期间手动改系统时间/自动校时会跳变（罕见，接受） |

### 实现要点（三处同步修改）

**`data/model/TimerState.kt`**：
```kotlin
TimerStatus.RUNNING -> accumulatedMs + (System.currentTimeMillis() - resumeElapsed)
```
（`PAUSED/IDLE/STOPPED` 分支不变；`SystemClock` import 若无用则移除。）

**`ui/timer/TimerService.kt`**：
- `startTiming()`：`val now = System.currentTimeMillis()`；
- `resumeTiming()`：`resumeElapsed = System.currentTimeMillis()`；
- `restoreTimerState(saved, currentWallMs)`：`offlineMs = currentWallMs - saved.resumeElapsed`，有效区间 `(0, 365天)` 时 `accumulatedMs += offlineMs`，随后 `resumeElapsed = currentWallMs`；
- 移除不再使用的 `SystemClock` import。

**`ui/main/MainScreen.kt`**：
```kotlin
TimerService.restoreTimerState(saved, System.currentTimeMillis())
```

## 四、加分后自动触发自证修复

### 现状问题（根因）

`MainViewModel.checkProof()` 用 `_userScoredFlag` 标记「用户普通加分」，每次 `settings` 发射就消费：

- `onConfirm` / 计时结算流程为：`notifyUserRecord()`（置标记）→ 协程内 **先 `markDeedDone()`（写 settings）→ 再 `addHistoryEntry()`（写 settings）**；
- `markDeedDone` 的 settings 发射先到达 `checkProof`：此时**总分还没变**，`newLevel == _lastLevel` 不弹窗，**但标记被消费**；
- 随后 `addHistoryEntry` 真正加分时标记已为 false → 不弹被动自证。

只有事件是「每日必做」时才发生，故表现为「有时候」。

### 决策

| 项 | 决策 |
|---|---|
| 修复方式 | 仅当 `totalScore` **实际发生变化**时才消费 `_userScoredFlag` |

### 实现要点

**`ui/main/MainViewModel.kt`（checkProof）**：
```kotlin
} else if (_userScoredFlag) {
    // 只有总分实际变化（用户加分写库）才消费标记；
    // 每日必做的 markDeedDone 会先写 settings 但总分未变，此时保留标记，等加分发射再判定。
    if (s.totalScore != _lastTotal) {
        _userScoredFlag = false
        val newLevel = ProofEngine.rankLevelOf(s.totalScore, s)
        if (s.proofEnabled && newLevel >= 1 && newLevel > _lastLevel && s.totalScore > _lastTotal) {
            _pendingPassiveProof.value = PassiveProofPrompt(_lastLevel, newLevel)
        }
    }
}
```
（末尾 `_lastTotal/_lastLevel` 更新逻辑不变。）

## 五、誓约终止时间改为可选时间 + 到期判定

### 需求（用户确认）

> 誓约的终止时间改成能选择时间（年月日第一行，时分秒第二行，参考业力衰减的设置时间方式，一开始默认当前时间），能判定每个誓约是否到期（和业力衰减判定和每日必做判断一起判断），如果到期弹出弹窗让你选择是否完成。

### 决策表

| 项 | 决策 |
|---|---|
| 时间选择形式 | 弹窗内两行 `ScrollPicker`：第一行 年/月/日，第二行 时/分/秒；默认当前时间 |
| 数据结构 | `Bet.deadline: String` → `Bet.deadlineAt: Long`（时间戳） |
| 到期判定 | 与业力衰减/每日必做一起：MainViewModel 2 秒循环 + 打开应用时立即判定 |
| 到期弹窗位置 | **首页**（MainScreen），与自证弹窗一致 |
| 弹窗结算 | 「完成」= +成功分；「未完成」= −失败分；两种情况都从列表移除誓约 |
| 旧誓约 | **清空**（迁移时 `bets = '[]'`） |

### 实现要点

**`data/local/entity/Bet.kt`**：
```kotlin
data class Bet(
    val content: String,
    val deadlineAt: Long,      // 终止时间戳（v4.3：原 deadline 纯文本改为时间）
    val successPoints: Float,
    val failurePoints: Float,
    val createdAt: Long,
)
```

**`KarmaDatabase.kt`**：v27 迁移中清空旧誓约（见第六节）。

**`KarmaRepository.kt`**：
- 新增 `formatDateTime(timestamp): String`（`yyyy-MM-dd HH:mm:ss`，仿 `formatDate`）；
- `addBet` / `resolveBet` 的历史事件文本由 `bet.deadline` 改为 `formatDateTime(bet.deadlineAt)`；
- 新增到期查询：
```kotlin
fun getExpiredBets(settings: KarmaSettingsEntity): List<Bet> =
    settings.bets.filter { it.deadlineAt in 1..System.currentTimeMillis() }
```

**`ui/bet/BetViewModel.kt`**：`addBet(content, deadlineAt, success, failure)`；新增 `resolveBet` 透传（已有）。

**`ui/bet/BetScreen.kt`**：
- `NewBetDialog`：删除「时间期限」文本输入，改为「终止时间」行（显示已选时间，点击弹出 `BetTimePickerDialog`）；默认当前时间；合法条件改为 `content` 非空 + 两个分数合法（时间恒有值）；
- 新增 `BetTimePickerDialog`：复用 `ScrollPicker`，第一行 年/月/日，第二行 时/分/秒；确定时按所选年月日时分秒构造时间戳；
- `BetRow` / `BetDetailDialog` 的期限显示改为 `formatDateTime(bet.deadlineAt)`。

**`ui/main/MainViewModel.kt`**：
- 新增 `_expiredBetPrompt = MutableStateFlow<Bet?>(null)` 与其 state；
- 2 秒周期循环内（`applyDecay` 之后）调用到期检查；init 中先做一次立即检查；
- 检查逻辑：`settings.first()` → `repository.getExpiredBets(s)`，若已有弹窗在显示则跳过，否则取第一个置入；
- 新增 `onExpiredBetComplete()` / `onExpiredBetFail()`：调用 `repository.resolveBet(bet, true/false)` 后清空 prompt。

**`ui/main/MainScreen.kt`**：
- 新增 `BetExpiryPromptDialog`（仿 `ProofResultDialog` 样式）：标题「誓约到期」，正文显示内容与终止时间，按钮「完成（+X 分）」/「未完成（−Y 分）」；
- 顶部渲染 `expiredBetPrompt?.let { ... }`。

## 七、数据层变更汇总

### Room version 26 → 27

```kotlin
private val MIGRATION_26_27 = object : Migration(26, 27) {
    override fun migrate(db: SupportSQLiteDatabase) {
        // 气运测试冷却（秒），默认 1.5
        db.execSQL("ALTER TABLE karma_settings ADD COLUMN luckTestCooldownSec REAL NOT NULL DEFAULT 1.5")
        // v4.3 起誓约终止时间由纯文本改为时间戳，旧誓约无法迁移 → 清空
        db.execSQL("UPDATE karma_settings SET bets = '[]'")
    }
}
```
并加入 `addMigrations(...)` 链。

### 导入/导出兼容（`KarmaRepository.importJson`）

新增字段兜底，避免旧导出缺键时 gson unsafe 置 0：
```kotlin
luckTestCooldownSec = gsonNullable(importedSettings.luckTestCooldownSec) ?: 1.5f,
```
旧导出中的誓约含 `deadline` 文本、无 `deadlineAt` → 反序列化后 `deadlineAt = 0`，`getExpiredBets` 以 `deadlineAt in 1..now` 过滤 → 不参与判定，不误弹。

## 十一、风险与备注

- 计时改用墙钟后，计时期间手动改系统时间会导致时长跳变（已确认接受）。
- 誓约日期选择不做「月份/闰年」天数联动（日固定 1~31，与用户确认一致），但确定时用 `daysInMonth(year, month)` 校验（含闰年 2 月 29 日）：非法（如 2 月 30 日）弹 Toast 提示且不关闭弹窗。
- 重置按钮除清 ViewModel 选择状态外，已在 `ScorePanel` 内同步清空本组件的自定义分数输入框；`EventPanel` 内部的自定义事件输入框为组件本地状态，本次未一并清空（需求只要求分数归 0、事件取消选中、乘法取消选中）。
- 旧誓约清空属破坏性操作，已在迁移中执行（用户确认）。
