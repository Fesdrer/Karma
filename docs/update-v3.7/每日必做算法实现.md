# 每日必做扣分机制 — 实现计划

## Context

每日必做功能的 UI 和设置持久化已完成，但扣分逻辑从未实现。用户要求将扣分机制嵌入现有的业力衰减算法中，并持久化 vis（今日已完成状态），使衰减算法能读取 vis 来判断哪些每日必做未完成。

## 用户伪代码（逐行翻译）

```
1. 保存设置时，某事件被设为每日必做 → vis=0(未做)
2. 在 decay 的"重复 需补扣天数 次"循环中，对每个每日必做事件：
   if vis=1 → 跳过
   else → 扣分，事件名 = "未完成：{事件名称}"
3. 循环完成后，if 需补扣天数>0 → 重置所有 vis=0（新的一天）
```

## 修改清单

### 1. `KarmaSettingsEntity.kt` — 新增两个持久化字段

```kotlin
// ===== 每日必做 vis 持久化 =====
val dailyMustDoLastDate: String = "",     // yyyy-MM-dd，vis 所属的日期
val dailyMustDoDoneSet: List<String> = emptyList(),  // 当日已完成的善业名列表
```

### 2. `KarmaDatabase.kt` — 新增 MIGRATION_11_12

```sql

ALTER TABLE karma_settings ADD COLUMN dailyMustDoDoneSet TEXT NOT NULL DEFAULT '[]'
```

版本号: `version = 11` → `version = 12`

### 3. `KarmaRepository.kt` — 修改 applyDecay() + 新增方法

**新增方法：**
```kotlin
suspend fun updateDailyMustDoDoneSet(doneSet: List<String>)
// 持久化当日已完成集合，供 decay 算法读取
```

**修改 `applyDecay()`：**
在已有的 `repeat(daysToCatchUp)` 循环体内，**在 decay 扣分之后**追加每日必做扣分：

```kotlin
// --- 每日必做扣分（step 2） ---
val dailyNames = settings.dailyMustDoDeedNames
val dailyPenalties = settings.dailyMustDoDeedPenalties
val currentDoneSet = dailyMustDoDoneSet.toSet()  // 当前 vis

for (i in dailyNames.indices) {
    val deedName = dailyNames[i]
    if (deedName in currentDoneSet) continue  // vis=1 → 跳过
    val penalty = dailyPenalties.getOrElse(i) { 1f }
    if (penalty > 0f) {
        currentScore = roundToOneDecimal(currentScore - penalty)
        totalDeducted += penalty
        historyDao.insertEntry(
            HistoryEntryEntity(
                timestamp = uniformTimestamp,
                delta = -penalty,
                event = "未完成：${deedName}",
                type = "daily_must_do",
                totalAfter = currentScore,
            )
        )
    }
}
```

**循环完成后（step 3）：**
```kotlin
// 如果补扣了天数，说明到了新的一天 → 重置 vis
val newDoneSet: List<String>
val newLastDate: String
if (daysToCatchUp > 0) {
    newDoneSet = emptyList()       // 所有 vis 重置为 0
    newLastDate = dateB            // 新的一天
} else {
    newDoneSet = dailyMustDoDoneSet
    newLastDate = dailyMustDoLastDate
}
```

**最终持久化（修改已有 `upsertSettings` 调用）：**
```kotlin
settingsDao.upsertSettings(settings.copy(
    totalScore = currentScore,
    lastDecayDate = dateB,
    dailyMustDoDoneSet = newDoneSet,
    dailyMustDoLastDate = newLastDate,
))
```

### 4. `MainViewModel.kt` — vis 与持久化双向同步

**初始化阶段**（在 init 的 combine 中或之后）：
- 从 `repository.settings` 读取 `dailyMustDoDoneSet` 和 `dailyMustDoLastDate`
- 如果 `dailyMustDoLastDate == 今天日期(yyyy-MM-dd)` → 用持久化的 set 作为初始 `_dailyMustDoDoneToday`
- 否则 → 置空（新的一天）

**`markDailyMustDoDone()` 修改**：
- 除了更新 `_dailyMustDoDoneToday`，还要调用 `repository.updateDailyMustDoDoneSet(newSet.toList())`

### 5. `SettingsViewModel.kt` — 保存时重置 vis

修改 `save()` 方法：
- 如果 `_draft.value.dailyMustDoDeedNames != _original.value.dailyMustDoDeedNames`（配置有变动）
- 调用 `repository.updateDailyMustDoState(emptyList(), 今天日期)` 重置 vis

或更简单：在 `save()` 调用 `repository.updateAllSettings(_draft.value)` 之后，额外调用重置。
但最准确的做法是只在配置确实改变时重置。由于 `save()` 中能比较 draft 和 original，可以在 `save()` 中添加这个逻辑。

## 数据流

```
settings 保存时配置变更
  → SettingsViewModel.save() 重置 vis → DB(dailyMustDoDoneSet=[], dailyMustDoLastDate=today)
  
应用启动/衰减触发
  → KarmaApplication → repository.applyDecay()
  → 读取 DB 中的 dailyMustDoDoneSet 和 dailyMustDoNames
  → 循环中扣分
  → 重置 vis（补扣天数>0时）

用户确认善行
  → MainViewModel.onConfirm() → markDailyMustDoDone()
  → 更新 _dailyMustDoDoneToday + repository.updateDailyMustDoDoneSet()
  → DB 同步
```

## 验证方式

1. 设置两个善业为每日必做（如"帮助他人"扣1分、"早起早睡"扣2分）
2. 保存设置后返回主页 → 两个都显示蓝色（未做）
3. 完成"帮助他人" → 变为绿色 → 重启应用 → 仍显示绿色（持久化）
4. 修改 decay 时间到当前时间之前 → 重新打开应用 → decay 触发补扣
   - 应扣除"早起早睡"的 2 分（"帮助他人"已做跳过）
   - 历史记录出现两条："业力衰减" 和 "未完成：早起早睡"
5. 再重启一次 → vis 已重置 → 两个都蓝色 → 应扣除两个未完成的分数
