# 任务3：新功能「誓约」——立下誓言，信守加分，违背减分

## 1. 功能定义（用户原话 + 已确认的决策）

- 底部栏在「祈福」和「占卜」之间新增「**誓约**」入口（**用户确认**：放底部栏，保持 14sp 字号；底部栏**加宽**——去掉左右 10dp 内缩，边框左右与上方分数栏左边/事件栏右边对齐）。
- 点击进入誓约页：显示当前**正在进行**的誓约列表。
- 右上角「+」→ 弹出填写表单，四个字段：**对赌内容**（纯文本）、**时间期限**（纯文本）、**成功加分**（正数）、**失败减分**（正数）。**用户确认**：失败减分填正数，失败时从总分中减去该数值。
- 点「确定」：历史记录新增 **4 行**的 `誓约：内容 / 期限 / +加分 / -减分`（每项一行，不用分隔符——历史显示支持换行，祈福记录已有 `\n` 先例），分数为 0；誓约出现在列表中（进行中）。
- 列表每行有 **✔**（成功）和 **×**（失败）按钮：
  - ✔ → 总分 +加分，历史新增 3 行 `誓约结果：内容 / 期限 / 成功`，分数为加的分数；该誓约从列表消失。
  - × → 总分 -减分，历史新增 3 行 `誓约结果：内容 / 期限 / 失败`，分数为减去的分数；该誓约从列表消失。
- 点击某条誓约 → 弹出详情小窗，查看完整信息。
- **用户确认**：不支持中途撤销——誓约立下后只能按 ✔ 或 × 了结。
- 内容、期限**纯文本**，不做任何额外判断/提醒/自动操作（不做"到期提醒"、"是否完成"的自动检测）。

### 命名决策（用户已确认）

| 决策点 | 结论 |
|---|---|
| 功能名 | **誓约**（不用"赌约"：赌博意味与善业世界观冲突；不用"目标"：缺少自我奖惩的分量感） |
| 入口 | 底部栏 6 分区，字号保持 14sp 不变 |
| 减分输入 | 填正数，失败时扣除 |
| 中途撤销 | 不支持 |
| 历史 type | 创建 `bet`，结果 `bet_result`（与 `record`/`prayer`/`divination` 并列） |

## 2. 历史记录格式（对齐现有约定）

现有约定：`祈福：xxx`（type=prayer）、`占卜：xxx`（type=divination）→ 誓约记录同样用「名字：」前缀。

**多行显示**（用户确认：不用 `|` 分隔符，四项直接分 4 行显示。历史显示支持换行，祈福记录已有 `\n` 先例）：

```
誓约：今天必须运动
本周内
+3
-2
```

| 时机 | event 文本（实际为 `\n` 连接的多行） | delta | type |
|---|---|---|---|
| 立下誓约 | `誓约：${内容}\n${期限}\n+${加分}\n-${减分}` | 0 | `bet` |
| ✔ 成功 | `誓约结果：${内容}\n${期限}\n成功` | +加分 | `bet_result` |
| × 失败 | `誓约结果：${内容}\n${期限}\n失败` | -减分 | `bet_result` |

数字格式化：加分/减分若为整数不显示小数点（`3` 而非 `3.0`），小数保留 1 位（`3.5`）。

## 3. 数据层设计

**决策**：进行中的誓约存进 `karma_settings` 表的一个 JSON 列（与「每日必做 dailyMustDoDeeds」完全相同的模式），**不新建数据库表**。

理由（因果链）：
- 新增列 = 数据库 v14→v15 一次 ALTER TABLE（与既有 13 次迁移同模式）。
- 新增表 = 也要 v14→v15，且导出/导入（JSON/CSV）需要额外处理新表，否则备份会丢誓约。
- JSON 列方案：`exportJson()` 整体序列化 settings → 誓约**自动**随备份导出；`importJson()` 整体反序列化 → 自动恢复，只需补一个空列表兜底。
- 誓约数量少（进行中最多几条），JSON 性能无压力。

### 3.1 新实体 `data/local/entity/Bet.kt`

### 3.5 `KarmaRepository.kt`：新增两个操作

```kotlin
// ---- 誓约 ----

/** 立下誓约：写入 bets 列表 + 历史记录（分数不变）。 */
suspend fun addBet(bet: Bet) {
    val settings = settingsDao.getSettingsOnce() ?: KarmaSettingsEntity()
    settingsDao.upsertSettings(settings.copy(bets = settings.bets + bet))
    addHistoryEntry(
        delta = 0f,
        // 四项分 4 行显示，不用分隔符（历史显示支持换行，祈福记录已有 \n 先例）
        event = "誓约：${bet.content}\n${bet.deadline}\n+${formatPoints(bet.successPoints)}\n-${formatPoints(bet.failurePoints)}",
        type = "bet",
    )
}

/** 了结誓约：success=true 加分，false 减分；从列表移除；写结果记录。 */
suspend fun resolveBet(bet: Bet, success: Boolean) {
    val settings = settingsDao.getSettingsOnce() ?: KarmaSettingsEntity()
    val delta = if (success) bet.successPoints else -bet.failurePoints
    settingsDao.upsertSettings(settings.copy(bets = settings.bets.filter { it != bet }))
    addHistoryEntry(
        delta = delta,
        event = "誓约结果：${bet.content}\n${bet.deadline}\n${if (success) "成功" else "失败"}",
        type = "bet_result",
    )
}
```

注意（因果链）：
- `resolveBet` 先写 bets 列表再调 `addHistoryEntry`（后者内部读 settings→改 totalScore→写）。两处对 settings 的读写在同一个 suspend 链中顺序执行，单用户场景无并发覆盖问题（与现有 `markDeedDone` 同模式）。
- `addBet` 走 `addHistoryEntry(delta=0f)`，与「分数为 0」的需求一致，且 totalAfter 自动更新为当前总分。
- `Bet` 是 data class，`filter { it != bet }` 按值相等即可正确匹配。

新增小工具函数（`formatPoints`）：整数去小数位，非整数保留 1 位：

```kotlin
private fun formatPoints(value: Float): String {
    return if (value % 1f == 0f) value.toInt().toString() else value.toString()
}
```

### 3.6 `KarmaRepository.kt` importJson 兼容旧备份

## 4. UI 层设计

### 4.1 新页面 `ui/bet/BetScreen.kt` + `ui/bet/BetViewModel.kt`

**ViewModel**（仿 PrayerViewModel 的 Factory 模式）：

```kotlin
class BetViewModel(private val repository: KarmaRepository) : ViewModel() {
    // CLAUDE.md 规则3：不用 stateIn(initialValue=emptyList) —— 首帧会闪"空列表"，
    // 用 MutableStateFlow<null>，UI 层 null 时不渲染列表区。
    private val _bets = MutableStateFlow<List<Bet>?>(null)
    val bets: StateFlow<List<Bet>?> = _bets.asStateFlow()

    init {
        viewModelScope.launch {
            repository.settings.collect { _bets.value = it.bets }
        }
    }

    fun addBet(content: String, deadline: String, success: Float, failure: Float) {
        viewModelScope.launch {
            repository.addBet(Bet(content, deadline, success, failure, System.currentTimeMillis()))
        }
    }

    fun resolveBet(bet: Bet, success: Boolean) {
        viewModelScope.launch { repository.resolveBet(bet, success) }
    }

    companion object {
        fun Factory(repository: KarmaRepository) = viewModelFactory { initializer { BetViewModel(repository) } }
    }
}
```

**Screen 结构**（仿 HistoryScreen 的「标题栏常驻、数据就绪再渲染内容」模式）：

## 5. 边界情况

| 情况 | 处理 |
|---|---|
| 分数可为负（现状） | 失败减分可能把总分扣成负数——`addHistoryEntry` 支持负 delta，totalAfter 自动为负，与现有衰减/恶业扣分一致，无需特判 |
| 数字输入非法（如 "abc"、"3.5.2"） | 确定按钮禁用，不写入 |
| 内容超长 | 行内 ellipsis，详情弹窗显示全文 |
| 旧版本备份导入（无 bets 键） | `?: emptyList()` 兜底，导入不失败 |
| 新安装用户 | bets 默认空列表 → 空状态提示 |
| 快速连点 ✔/× | suspend 链顺序执行；resolve 后列表立即移除该行（Flow 刷新），第二次点击已无此对象 |
| 立誓约时历史记录 delta=0 | `addHistoryEntry(0f, ...)` → 总分不变，历史出现一条 0 分记录（总分线无跳变，符合需求「分数为0」） |
