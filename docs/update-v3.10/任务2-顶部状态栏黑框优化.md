# 任务2：顶部状态栏黑框优化

## 1. 现象

除底部导航栏外，屏幕**顶部**也有一条黑框（显示时间、电池、信号等系统图标）。该条在部分手机上是一条与 App 背景有明显分界的黑色横条。

## 2. 当前方案（已通读代码）

| 位置 | 现状 |
|---|---|
| `MainActivity.kt` | `enableEdgeToEdge()`（正确，在 `super.onCreate` 之前）→ 然后**手工把状态栏/导航栏设为不透明 `#0a0a0a`**，并固定浅色图标 |
| `themes.xml` | `windowBackground` / `statusBarColor` 均为 `#0a0a0a` |
| `Theme.kt` | 全屏 `Brush.verticalGradient(gradientColors)` —— **背景是用户可配置的渐变**（设置页有颜色选择器，可任意取色），星星图片在渐变之上、`statusBarsPadding()` 之下 |
| 各页面 | 根容器 `statusBarsPadding()`，内容顶到栏下方 |
| `ScriptureOverlay` | **硬编码 `topPadPx = 56dp` / `botPadPx = 56dp`** |

## 3. 为什么"不智能"（问题的根源）

1. **两段代码互相矛盾**：先 `enableEdgeToEdge()`（系统栏透明、内容延伸到栏后），紧接着手工把状态栏设成**不透明黑色** —— 系统于是在顶部绘制了一条纯色黑条，压住 App 自己的渐变背景。栏色（固定 `#0a0a0a`）与背景色（用户可配置渐变）必然存在色差 → 这就是那条"黑框"。
2. **跨版本行为不一致**：API 35+ 上 `window.statusBarColor` 被系统强制忽略（edge-to-edge 强制），同一份代码在不同手机上"有时生效有时不生效"，视觉表现不可控。
3. **颜色不随主题自适应**：栏色永远硬编码 `#0a0a0a`，不理会用户配置的渐变颜色——"黑框"与背景永远有色差。正确做法是**让 App 自己的背景延伸到栏后**，系统根本不绘制"框"。
4. **图标对比度硬编码**：`isAppearanceLightStatusBars = false`（永远浅色图标）。渐变顶色是用户可配置的，若用户选了**浅色**渐变，浅色图标会看不见。
5. **56dp 魔法数字**：经文画面上下预留假设固定栏高。刘海屏/高 inset 机型会不准（上方），手势导航机型底部会多出空白（下方）。

## 4. 优化方案（核心思路：消除系统绘制的"框"，让 App 背景接管栏后区域）

### 4.1 MainActivity：删除手工设置栏色的代码
删除 `window.statusBarColor` / `window.navigationBarColor` 两行（与 `enableEdgeToEdge()` 冲突、API 35+ 被忽略、`themes.xml` 已有同款默认值，纯冗余）。
- 效果：状态栏区域显示的是 **App 自己的渐变背景 + 浅色图标悬浮其上** → 任何机型、任何栏高、任何刘海都不会再有"黑框"。
- 底部导航栏同理 → 三键手机的按钮区域也不再是纯黑条（配合任务1的 `navigationBarsPadding` 布局适配）。
- 图标外观设置（`isAppearanceLightStatusBars` / `isAppearanceLightNavigationBars`）**保留**，默认深色主题下浅色图标正确。
- 老机型（API 24-28）透明效果需实机确认；若个别机型出现异常，保留 `themes.xml` 的 `statusBarColor` 作兜底默认值即可。

### 4.2 图标对比度随主题自适应（真正"智能"的部分）
在 `Theme.kt`（已有 `settings` 和 `gradientColors`）中用 `Color.luminance()` 判断渐变顶部色明暗：
- 顶色偏暗（默认深色渐变）→ 浅色图标（现状）
- 顶色偏亮（用户选了浅色渐变）→ 深色图标

实现方式：`LocalView.current` + `WindowCompat.getInsetsController(window, view)`，在 `LaunchedEffect(gradientColors)` 里按明暗设置 `isAppearanceLightStatusBars` / `isAppearanceLightNavigationBars`。这样无论用户把渐变配成什么颜色，顶部图标永远可读。

### 4.3 经文画面：56dp 魔法数字 → 真实 inset
`ScriptureOverlay` 里把 `topPadPx` / `botPadPx` 从固定 56dp 改为读取真实 `WindowInsets.statusBars` / `WindowInsets.navigationBars`（Canvas 的 DrawScope 本身是 Density，可直接换算）。
- 上方：任何机型的刘海/栏高都精确避让；
- 下方：手势导航机型（inset=0）不再多出无意义的空白，三键机型精确贴合栏高。

### 4.4 themes.xml
`windowBackground #0a0a0a` 保留（冷启动底色，避免闪变）；`statusBarColor` 保留作老机型兜底默认。

## 5. 边界与风险

1. 透明栏后主页面顶部渐变会延伸到状态栏后面（星星图片仍在栏下方，因 `Theme.kt` 里图片有 `statusBarsPadding`）——属预期效果，实机确认视觉。
2. 键盘弹出、对比度 scrim 由系统默认处理，不在本任务范围。
3. API 24-28 老设备上透明栏的兼容性需实机验证，必要时兜底。
4. 本任务与任务1配合：任务1解决"内容被遮挡"（布局），本任务解决"系统绘制的黑框"（栏样式），两者相加才能让上下黑框问题完整消失。

## 6. 实施与验证清单

1. 删除 MainActivity 两行栏色赋值 → 编译 → 实机看顶部是否还有黑框（三键/手势机型各一台）。
2. 实现 4.2 图标明暗自适应 → 设置页把渐变顶色改为浅色 → 确认图标变深色、可读；改回深色 → 恢复浅色图标。
3. 实现 4.3 经文画面真实 inset → 刘海屏机型确认经文上边框避让正确；手势机型确认底部不再多出空白。
4. 全流程回归：任务1 + 任务2 改动后，主页面 / 占卜页 / 祈福页 / 历史页 / 设置页在两种机型上均无黑框、无遮挡。
