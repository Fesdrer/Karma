### BUGFIX-A：分数清零

**现象**：在设置页面修改任意参数后保存，总分变成 0。

**根因**：`SettingsViewModel` 中 `_draft` 初始化为 `KarmaSettingsEntity()`（totalScore=0）。如果用户在 DB 加载完成前编辑了任意设置，`_userEdited = true`，DB 加载后不覆盖 draft，但 draft 的 totalScore 一直是 0，保存时写入 0。

**修复位置**：`app/src/main/java/com/example/karma/ui/settings/SettingsViewModel.kt`（已修复）
- 在 `init` 的 `if (!_userEdited)` 分支后增加 `else` 分支，合并保留 `totalScore` 和 `lastDecayDate`。

### BUGFIX-B：启动闪退 — java.time API 兼容性

**现象**：在 API 24/25 设备上打开应用即闪退。

**根因**：`LocalDate.ofInstant()`、`ChronoUnit` 等 `java.time` API 需要 API 26+，但 `minSdk = 24`。

**修复位置**：`app/src/main/java/com/example/karma/data/repository/KarmaRepository.kt`（已修复）
- 将所有 `java.time.*` 导入替换为 `java.util.Calendar`。
- 用 `Calendar` 实现日期计算和时间戳生成。

## 待修复的问题（下个AI需处理）

### BUG 1：业力衰减重复扣除 + 算法重写

#### 问题描述

- 每次打开应用，历史记录中出现大量（几十到上百条）"业力衰减"记录
- 每条记录只显示 -2 或 -3 分，但总分变成很大的负数（如 -320）
- 这是由于衰减从第一条历史记录开始逐日补扣，如果有 160 天历史数据，就会扣 160 次

#### 根因分析

**两个问题叠加**：

1. **双重调用**：`applyDecay()` 在 `KarmaApplication.onCreate()` 和 `MainViewModel.init` 中都被调用，竞态条件导致历史条目翻倍。不过分数计算结果相同（都从原始 totalScore 开始计算），所以分数异常的主因是下面第二点。

2. **追溯范围过大**：`lastDecayDate` 为空时，代码从第一条历史记录的日期的前一天开始补扣到今日。如果导入或生成过大量历史测试数据（如从 1 月到 6 月），会一次性扣除 160+ 天的分数（160 × 2 = 320 分）。

#### 用户要求的新算法

```
衰减按钮默认关闭。

当用户设置完时间，打开衰减按钮时：
  记录当前日期为"日期A"（lastDecayDate）
  显示在设置页的"上次扣除"位置

函数 F（每次打开应用 或 打开衰减开关时执行）：
  if 衰减按钮关闭 → 不做任何事，直接返回
  
  日期B = 今天
  if 当前时间 已超过 设定时间（如 23:00）：
      日期B = 明天
  // 日期B 表示"应该扣除到哪一天"
  
  while 日期A < 日期B：
      按当前阶位扣除分数
      时间戳统一设为"此刻"（System.currentTimeMillis()）
      日期A++
  // 更新日期A到数据库
```

**算法逻辑说明**：
- 衰减只在日期A < 日期B 时触发，不会追溯开启之前的日期
- "超过设定时间"的判断：如果当前时间 >= 设定的时:分 → 今天已过截止时间，日期B=明天；否则日期B=今天
- 举例：设定 23:00，当前 22:00 → 日期B=今天，不触发扣除；当前 23:30 → 日期B=明天，扣除今天的分数
- 时间戳统一用当前时间（所有补扣记录共享同一个时间戳）

#### 需要修改的文件

**① `data/local/entity/KarmaSettingsEntity.kt`**
- `decayEnabled: Boolean = true` → 改为 `= false`（默认关闭）

**② `data/repository/KarmaRepository.kt`**
- 重写整个 `applyDecay()` 方法，按照上述新算法
- `lastDecayDate` 为空时 → 设置 `lastDecayDate = today` 并返回 0（不做追溯扣除）
- 删除原来的 `formatDate()` 辅助函数（已存在），可以用简化实现：

```kotlin
private fun formatDate(timestamp: Long): String {
    val cal = Calendar.getInstance().apply { timeInMillis = timestamp }
    return String.format("%04d-%02d-%02d",
        cal.get(Calendar.YEAR),
        cal.get(Calendar.MONTH) + 1,
        cal.get(Calendar.DAY_OF_MONTH))
}
```

**③ `ui/main/MainViewModel.kt`**
- 删除 `init` 块中整个 `viewModelScope.launch { repository.applyDecay() ... }` 代码块
- 只在 `KarmaApplication` 中调用一次即可

**④ `ui/settings/SettingsViewModel.kt`**
- 在 `updateDecayEnabled(true)` 中，当 `lastDecayDate` 为空时，设为今天：

```kotlin
fun updateDecayEnabled(v: Boolean) {
    if (v && _draft.value.lastDecayDate.isEmpty()) {
        val cal = Calendar.getInstance()
        val today = String.format("%04d-%02d-%02d",
            cal.get(Calendar.YEAR),
            cal.get(Calendar.MONTH) + 1,
            cal.get(Calendar.DAY_OF_MONTH))
        setDraft(_draft.value.copy(decayEnabled = true, lastDecayDate = today))
    } else {
        setDraft(_draft.value.copy(decayEnabled = v))
    }
}
```

### BUG 2：时间选择器无法循环滚动

#### 问题描述

设置页 → 业力衰减 → 扣除时间。滚动选择器到 23（或 59）后没有更多项，不会循环回 0。

#### 根因

`ScrollPicker` 的 `LazyColumn` 使用固定范围列表 `0..23` / `0..59`，滚动到末尾就没了。

#### 修复方案

**文件**：`app/src/main/java/com/example/karma/ui/settings/SettingsScreen.kt`

将 `ScrollPicker` 的列表重复 3 份，初始定位到中间副本，选中值通过对 `baseSize` 取模归一化。在 `LaunchedEffect` 中添加边缘检测，滚动到边缘时无动画跳转到中间副本。

关键修改点：

```kotlin
@Composable
private fun ScrollPicker(
    range: IntRange,
    selected: Int,
    onSelected: (Int) -> Unit,
    modifier: Modifier = Modifier,
) {
    val baseItems = range.toList()
    val baseSize = baseItems.size

    // 重复 3 份实现循环效果
    val items = remember(range) {
        buildList { repeat(3) { addAll(range.toList()) } }
    }
    val totalSize = items.size

    val itemHeight = 44.dp
    val visibleItems = 5
    val scope = rememberCoroutineScope()

    // 初始定位在中间副本（第 2 份），并让选中项居中
    val startIndex = baseSize + baseItems.indexOf(selected).coerceAtLeast(0) - visibleItems / 2
    val listState = rememberLazyListState(
        initialFirstVisibleItemIndex = startIndex.coerceAtLeast(0)
    )

    // 计算正中间的项
    val centerItemIndex by remember {
        derivedStateOf {
            val layoutInfo = listState.layoutInfo
            if (layoutInfo.visibleItemsInfo.isEmpty()) return@derivedStateOf 0
            val viewportCenter = layoutInfo.viewportEndOffset / 2
            layoutInfo.visibleItemsInfo.minByOrNull { info ->
                abs((info.offset + info.size / 2) - viewportCenter)
            }?.index?.coerceIn(0, totalSize - 1) ?: 0
        }
    }

    // 选中值通过取模归一化到 base 范围
    LaunchedEffect(centerItemIndex) {
        onSelected(baseItems[centerItemIndex % baseSize])
        // 边缘检测：接近边界时跳回中间
        if (centerItemIndex < baseSize) {
            listState.scrollToItem(centerItemIndex + baseSize)
        } else if (centerItemIndex >= baseSize * 2) {
            listState.scrollToItem(centerItemIndex - baseSize)
        }
    }

    // ... 其余 UI 代码不变（高亮条、LazyColumn、item 显示等）
}
```

注意：需要在文件顶部添加缺失的 import：
```kotlin
import androidx.compose.runtime.derivedStateOf
import kotlin.math.abs
```
