# Karma v4.0 更新记录

## 上下文

本次更新从 v3.13 出发，共 39 个提交（改1~改39），主线是**阶位自证**（全新玩法）、**乘法功能**、**设置体系重构**，以及大量体验优化与并发 Bug 修复。开发过程中还完整实现过**闹钟功能**（改14~改21），最终因华为系统频繁杀进程导致体验不可靠，按用户要求整体移除（改22）。

所有修改均已通过 `:app:compileDebugKotlin` 编译验证。

**版本**：`build.gradle.kts` versionName "3.13" → "4.0"，versionCode 21 → 22。

## 一、阶位自证（★ 核心新功能，改26~改39）

### 需求（用户多轮确认）

"配得上这个阶位吗？"——自证考验**上去的能力 + 保持的能力**：

- 起点阶位 x：
  - 主动自证：x = 自证开始时的阶位
  - 被动自证：x = **加分前**的阶位
- 规则：
  1. 整个时长内，任何时刻阶位低于 x → 立即失败（考验保持能力）
  2. 时长结束时，当前阶位 y > x → 成功（恭喜登上结束时的实际阶位 y）；否则失败
- 达标**不能提前成功**——必须撑到时长结束（这是对"配"的完整考验）
- 业力衰减可能把分数减下去，因此自证时长必须覆盖衰减时刻
- 只有正阶位需要自证；自证中徽章停留在起点阶位
- 被动自证：加分跨入正阶位时弹询问窗，可选设置自证或逃避（扣分退回）

### 实现

**数据层（改26）**：`KarmaSettingsEntity` 新增 14 个字段——开关 `proofEnabled`、6 个特效颜色（`proofLineColor`/`proofGlowColor`/`proofCountdownBg`/`proofCountdownText`/`proofSuccessColor`/`proofFailColor`）、进行中状态（`proofActive`/`proofStartTime`/`proofDurationMs`/`proofStartRankLevel`/`proofTargetLevel`/`proofGuardLevel`）、奖励惩罚（`proofReward`/`proofPenalty`）。DB v20 → v23（v21 闹钟、v22 删闹钟、v23 自证）。

**核心逻辑（改27）**：`data/model/ProofEngine.kt` 纯函数：
- `rankLevelOf(score, settings)`：分数 → 阶位 level（正阶 1..N，负阶 -1..-9）
- `nextPositiveRankLevel` / `thresholdOf` / `distanceToNextPositiveRank`（<10 分判定）
- `minDurationToCoverDecay`：衰减开启时返回覆盖下一衰减时刻的最短时长
- `isDowngraded`（阶位 < 起点 x）与 `isEndSuccess`（结束时 y > x）

**MainViewModel（改27~改39）**：
- `requestActiveProof()` 主动开启（弹设置窗）；`onPassiveProofSetup()` 被动转设置；`onPassiveProofEscape()` 逃避扣分到新阶位阈值-1
- `startProof(reward, penalty, durationMs)` 开始自证；`finishProof(s, success)` 结束（重置状态 + 加/扣分 + 弹结果窗，防重入）
- `checkProof(s)`：settings 每次变化判定——开关关闭强制失败；**阶位 < 起点 x 立即失败**；**不在此判成功**（成功只在时长结束由超时协程判定 `isEndSuccess`）
- 每秒超时兜底协程：`proofActive && now >= startTime + durationMs` → 判定 y > x
- 自证期间徽章停留：`displayRank = proofActive ? ranks.find{level==proofStartRankLevel} : actualRank`
- 被动触发检测：仅用户普通记录加分（`_userScoredFlag`）时检测跨入正阶位，自证奖励/惩罚/逃避不触发

**设置页（改28）**：新增「自证」分类（开关 + 6 色 ColorSettingRow + ColorPickerDialog）；重置分组新增 PROOF（只重置开关+颜色，不动进行中状态）

**主页面交互（改29）**：Footer 新增自证按钮（誓约右边，`proofEnabled` 才显示，"自证中"不可点）；三个弹窗：`PassiveProofPromptDialog`（设置/逃避）、`ProofSetupDialog`（时:分滚轮 + 奖励惩罚 + 衰减覆盖校验）、`ProofResultDialog`（恭喜登临 y / 自证失败）

**数轴特效（改30、改32、改38）**：`AxisCanvas` 自证模式——粗线 + 光晕粒子循环（2600ms 从下往上）+ 红点变倒计时圆边矩形（每秒刷新 HH:MM:SS）；后改为**渐变亮斑线**（线色→光晕色→线色的正弦波平方波形，4 个亮斑从下往上流动，替代突兀的白色圆点粒子）

## 二、乘法功能（改8~改12、改23~改24）

- 主页面左栏分数栏底部**乘法按钮列**（2/3 分数 + 1/3 乘法），点击后当前分数 × 倍率，结果四舍五入到 0.5
- 设置页「乘法功能」分类：事件式列表增删改（倍率名 + 数值）
- 倍率用**分数类（Fraction）**存储与显示：输入 1/7 保持 1/7，不转小数（改12）
- 导入 JSON 兼容乘法分数：旧 Float 数组 / 新对象数组均可（改23），缺键补默认乘数（改24）

## 三、设置体系重构（改3、改4、改7）

- 「事件管理」与「每日必做」拆分为两个独立分类（改3）
- 原「通用」改名为「重置」，从整体重置改为**选择性重置**：分组勾选（外观/事件/乘法/自证/业力/启动/誓约/历史/计时/占卜）+ 全选/全不选，可单独重置历史记录等数据项（改4、改7）
- 选择事件时仅当当前分数为 0 才自动填默认分数（用户已选分数保持不变）（改5）

- 左栏分数拖动只在整数和 .5 位置停留吸附；占卜上限 0 显示"该阶位无法占卜"（改1）

## 五、闹钟功能（改14~改22，开发后移除）

完整实现了闹钟：数据层（AlarmEntity+DAO+DB v21）、调度响铃（setAlarmClock+接收器+响铃服务+全屏页+重启恢复）、UI（列表+新建/编辑：时间滚轮/重复/事件/铃声/震动/贪睡）、精确闹钟权限与降级、应用内铃声选择（规避华为系统铃声选择器切后台被杀）。

**但**：华为（旧鸿蒙/AOSP 12 底层）持续在响铃时杀进程，日志无 FATAL EXCEPTION，只有 `StopActivityItem`+`trimMemory`+`kill reason ... by app`——系统行为而非崩溃。用户最终决定：**"算了，把闹钟删了吧"**。改22 整体移除：删除整个 alarm 模块 + DB v22 迁移删 alarms 表 + 还原 Footer/导航/Manifest。

## 附注

- 用户测试自证时多次报告"弹错弹窗"，最终收敛为**两个叠加的并发 bug**（改34 的整行写覆盖 + 改35 的 flag 残留），以及一个**逻辑错误**（改36 的达标立即成功被用户明确纠正为"全程保持"），体现了"用户描述的现象顺序 = 代码执行顺序"的排查方法。
- 华为旧鸿蒙设备是主要测试机：`adjustResize` 失效（用 imePadding 解决）、系统铃声选择器切后台被杀（闹钟弃用原因之一）。
