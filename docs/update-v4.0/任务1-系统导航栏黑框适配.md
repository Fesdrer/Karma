# 任务1：根据有无系统导航栏（黑框）自动调整 UI 布局

## 1. 现象与原理

- Android 手机底部有两种导航方式：
  - **三键导航**：底部有一条实心黑色系统栏，显示「返回 / 桌面 / 最近任务」三个按钮（即用户说的"黑框"）。
  - **手势导航**：没有这条栏，内容直接延伸到屏幕底部。
- 本应用已启用 edge-to-edge（`MainActivity.enableEdgeToEdge()`），内容绘制在系统栏后面；`themes.xml` / MainActivity 把系统导航栏背景设为 `#0a0a0a`，与 App 深色背景一致 → 三键手机上这条系统栏看起来就是一条"黑框"。
- 结论：**不是要"隐藏"黑框（那是系统控件，App 无法也不应隐藏），而是让布局内容避开它**——黑框存在时底部内容上移，不存在时保持贴底。

## 2. 核心方案：用 `WindowInsets.navigationBars` 判定，而非手动判断模式

系统会向 App 报告导航栏 inset（底部高度）：

| 手机导航方式 | navigationBars 底部 inset | 视觉 |
|---|---|---|
| 三键导航 | ≈ 48dp | 有黑框 |
| 手势导航 | 0（绝大多数设备） | 无黑框 |

Compose 提供 `Modifier.navigationBarsPadding()`：**只在 inset > 0 的方向加 padding**。天然就是"有黑框才加间距、无黑框不加"，无需任何手动模式判断。这正是"根据有无黑框调整 UI 布局"的官方标准做法。

代码路径：inset 由 `enableEdgeToEdge()` + Compose 自动提供，无需额外配置。

**明确不做**（防止猜测性修复）：
- ❌ 不用反射读 `Settings.Secure` 的 `NAVIGATION_MODE` 判断手势/三键模式——没有公开 API，跨 OEM / 系统版本脆弱，且布局需要的只是"黑框高度"，inset 直接给出，无需绕道。
- ❌ 不全局硬编码 48dp——三键手机的实际栏高因设备而异（部分设备更高），硬编码会不准。

## 3. 现状盘点（已通读代码的结论）

| 页面 | 顶部处理 | 底部处理 | 现状 |
|---|---|---|---|
| MainScreen（主页面） | Scaffold innerPadding | Scaffold 默认 `contentWindowInsets = systemBars`，innerPadding 已含底部导航栏 inset | **大概率已自适应**，实施时实机确认即可 |
| DivinationScreen（占卜页） | `statusBarsPadding()` | 底部 tab bar `align(Alignment.BottomCenter)` | **三键手机上被黑框遮挡** |
| PrayerScreen（祈福页） | `statusBarsPadding()` | 底部元素（BottomEnd） | **底部元素可能被遮挡** |
| HistoryScreen（历史页） | `statusBarsPadding()` | 内容 Column | **底部内容可能被遮挡** |
| SettingsScreen（设置页） | `statusBarsPadding()` | 滚动内容 | **底部内容可能被遮挡** |
| ScriptureOverlay（经文启动画面） | 硬编码 `topPadPx = 56dp` | 硬编码 `botPadPx = 56dp` | 固定预留，与真实栏高近似但不精确（可选优化） |

## 4. 修改方案（逐文件）

### 4.1 DivinationScreen.kt
根 `Box`：`Modifier.statusBarsPadding()` 追加 `.navigationBarsPadding()`。
- 效果：黑框存在时整个内容区（含底部 tab bar）上移；无黑框时布局不变。
- 注意点：`XiaoLiuRenPillarCanvas` 注释明确设计为"图片贴到屏幕最底部"。根 Box 加 `navigationBarsPadding` 后图片底边会上移，与设计意图冲突。**备选**：只给底部 tab bar `Row` 加 `navigationBarsPadding`（tab bar 上移避开黑框、画布仍贴底）。
- 实施时两种做法都试，以实机视觉效果为准（改完必须实机验证）。

### 4.2 PrayerScreen.kt
根 `Box`：`Modifier.statusBarsPadding()` 追加 `.navigationBarsPadding()`。

### 4.3 HistoryScreen.kt
根 `Column`：`Modifier.statusBarsPadding()` 追加 `.navigationBarsPadding()`。

### 4.4 SettingsScreen.kt
根容器（`statusBarsPadding()` 所在处）：追加 `.navigationBarsPadding()`。

### 4.5 MainScreen.kt
验证 Scaffold innerPadding 是否已包含底部导航栏 inset：
- 已包含 → Footer 已被垫高，**不改**。
- 未包含 → 在 Column 上补 `navigationBarsPadding()`。

### 4.6 ScriptureOverlay（可选，本次不做，留待后续）
把固定 56dp 上下预留改为读取 `WindowInsets.statusBars` / `WindowInsets.navigationBars` 动态值，让经文画面在任意机型上都精确居中于可视区。

## 5. 边缘情况说明

1. **部分国产 OEM（如小米 MIUI）手势导航下仍会报告非 0 底部 inset**（手势条区域）：会多出少量空白，无害，可接受。
2. Android 15（API 35）对所有 targetSdk 35 的应用强制 edge-to-edge，正确处理 insets 是合规前提；本项目当前 targetSdk 34 不受强制，但本方案提前适配无风险。
3. 键盘弹出（`imePadding`）不在本任务范围。
4. 系统栏配色问题见**任务2-顶部状态栏黑框优化.md**（核心方案是让 App 背景接管栏后区域，消除系统绘制的黑框）；本任务只解决"内容被黑框遮挡"的布局问题。
