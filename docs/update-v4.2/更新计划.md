# Karma v4.2 更新计划

## 上下文

本次更新从 v4.1 出发，含**两个改动**，均经用户逐条选择题确认方案后实施：

1. **祈福神秘符号画板**：祈福输入弹窗内（除扣减分数/祈福目的/添加神明外）新增「绘制神秘符号」开关与手绘画板，画作仅供本次祈福自赏，**不入事件记录、不持久化、不进粒子动画**。
2. **业力衰减 + 每日必做 2 秒周期判定（方案 A）**：衰减/每日必做判定从「仅冷启动与开关切换触发」改为「进程存活期间每 2 秒轮询」，保证前台运行/计时/自证过程中跨过衰减时刻也能准点补扣；进程被杀后仍由启动补扣兜底（维持项目「非 AlarmManager」决策）。

**版本**：`build.gradle.kts` versionName "4.1" → "4.2"，versionCode 23 → 24。

---

## 一、祈福神秘符号画板

### 需求（用户确认）

> 输入祈福的时候，除了扣分、事件、神明，模仿"神明"加入一个能画神秘学符号的东西——就是一个画板能手动绘画，只是事件记录里不要把这个图画放进去。

### 决策表（用户选择题确认）

| 项 | 决策 |
|---|---|
| 入口形式 | 仿「添加神明」开关（行「绘制神秘符号」+ Switch，开启展开画板） |
| 画板高度 | 占祈福弹窗可视区一半以上（弹窗整体可滚动） |
| 绘画方式 | 纯自由手绘（无预设模板），附「清空」按钮 |
| 画笔颜色 | 固定红色（0xFFFF0000，与祈福文字一致） |
| 画作去向 | **不进粒子动画，仅画板自赏** |
| 持久化 | 不持久化（离开祈福页即弃，不进 JSON 导出） |
| 历史记录 | 事件文本完全不变（祈福：目的 / 神明），不提图画、不含图 |

### 实现要点

**`PrayerViewModel.kt`（PrayerUiState + 方法）**：
- 状态新增：`showSymbolBoard`（开关）、`symbolStrokes: List<List<Offset>>`（已完成的笔画）、`currentSymbolStroke: List<Offset>`（进行中的笔画）。
- 笔画坐标**归一化到 0..1**（相对画板尺寸），旋转/画板尺寸变化后仍可正确重绘。
- 方法：`toggleSymbolBoard()`、`startSymbolStroke(point)`、`addSymbolPoint(point)`、`endSymbolStroke()`（≥2 点才算一笔，并入已完成列表）、`clearSymbol()`。

**`PrayerScreen.kt`（UI）**：
- 神明输入区下方新增「绘制神秘符号」开关行（样式与「添加神明」一致：金色标题 + 金色 Switch）。
- 开关开启后渲染 `SymbolBoard`（高度 ≈ 屏高 50%，圆角暗底 + 金色细描边），内部 `Canvas`：
  - `onSizeChanged` 记录画布尺寸；`pointerInput(canvasSize)` + `detectDragGestures` 采集手指轨迹，换算成归一化坐标回调 ViewModel；
  - 逐笔画渲染（Path + red Stroke，圆头圆角），已完成笔画与进行中笔画分开；
  - 无笔画时中央淡提示「手指在此绘制神秘符号」；
- 画板下方「清空」TextButton。
- `confirmPrayer()` 不读取画作 → 历史/动画完全不受影响。

**不涉及**：数据层（无 Room 字段、无迁移）、事件记录、JSON 导入导出。

## 二、业力衰减 + 每日必做 2 秒周期判定（方案 A）

### 现状问题

`applyDecay()`（含每日必做扣分与 vis 重置）目前只在两处触发：

1. `KarmaApplication.onCreate()` 冷启动补扣；
2. 设置页开启「启用衰减」开关时（`SettingsViewModel.updateDecayEnabled`）。

因此应用**前台持续运行跨过衰减时刻（23:00）或跨天时不会判定**——计时（打坐，含熄屏前台服务）或自证进行中跨过 23:00，衰减/每日必做不发生，与「每天固定时间自动扣分」「自证时长必须覆盖衰减时刻」的设计意图相悖（v4.2-改1 前实测现象）。

### 决策表（用户选择题确认）

| 项 | 决策 |
|---|---|
| 判定方式 | 方案 A：进程存活期间每 **2 秒**轮询 `applyDecay()` |
| 载体 | **MainViewModel 级协程**（主入口常驻导航栈底，跨页面/计时期间持续生效） |
| 每日必做 × 衰减开关 | 保持现状：`decayEnabled=false` 时 `applyDecay` 早退 → 每日必做一并停摆（不新增解耦） |
| 「一天」边界 | 保持现状：到衰减时刻即视为进入新一天（扣当天未完成 + 重置 vis） |
| 进程被杀 | 维持「启动补扣」兜底，不引入 AlarmManager/WorkManager |
| 计时途中 | 照常扣分；停止结算读 DB 最新总分（`addHistoryEntry` 原子列更新） |
| 自证途中 | 照常生效：衰减把阶位打到起点以下 → 立即自证失败（符合 v4.0 设计） |
| 扣分提示 | 静默写库（Room flow 自动刷新主屏），不加弹窗/通知 |

### 必须顺带修复的并发隐患（v4.2-改4）

`applyDecay()` 尾部目前用**整行 `upsertSettings(settings.copy(...))`** 落库：先读整行快照、再全列写回。改成 2 秒轮询后与以下操作并发时会**用旧快照覆盖并发写入的字段**（正是 v4.0-改34 修过的 bug 类型）：

- `startProof/finishProof` 写 `proofActive/proofStartTime/...`（自证状态）；
- `addHistoryEntry`（总分）、`markDeedDone`（每日必做 vis）、计时器持久化。

**修复**：新增原子 `@Query UPDATE`，把 applyDecay 的三处落库改成**只更新本函数负责的列**：

- `KarmaSettingsDao` 新增：
  - `updateDecayResult(score, lastDate, deeds)` → 一次更新 `totalScore + lastDecayDate + dailyMustDoDeeds`（保持三者同一 SQL 原子提交）；
  - `updateLastDecayDate(lastDate)` → `lastDecayDate` 单列（空日期初始化分支用，不再整行写回）。
- `KarmaRepository.applyDecay()`：空日期分支与结尾落库改用上述原子方法。

历史插入（`historyDao.insertEntry`）不变；衰减/每日必做共用 `uniformTimestamp` 的行为不变。

### 实现要点

**`KarmaSettingsDao.kt`**：新增上面两个 `@Query UPDATE`。

**`KarmaRepository.kt`（applyDecay）**：
- 空日期分支：`settingsDao.upsertSettings(settings.copy(lastDecayDate = todayStr))` → `settingsDao.updateLastDecayDate(todayStr)`；
- 结尾：`settingsDao.upsertSettings(settings.copy(totalScore=…, lastDecayDate=dateB, dailyMustDoDeeds=newDeeds))` → `settingsDao.updateDecayResult(currentScore, dateB, newDeeds)`。

**`MainViewModel.kt`（init）**：新增与自证超时兜底并列的协程：
```kotlin
// 业力衰减 & 每日必做：2 秒周期判定（v4.2）
viewModelScope.launch {
    while (true) {
        delay(2000)
        try { repository.applyDecay() } catch (_: Exception) { /* 单次失败不中断轮询 */ }
    }
}
```
（`applyDecay` 幂等：`lastDecayDate ≥ dateB` 直接返回 0，不重复扣；跨过衰减时刻后下一轮轮询自动补扣并重置 vis。）

## 五、验证

1. `:app:compileDebugKotlin` 编译通过（每步提交前）。
2. 祈福：开关开启 → 画板出现（约半屏）→ 手绘红色笔画 → 清空 → 确认祈福 → 历史事件仍为文本（无图）、粒子动画不受影响。
3. 衰减：把衰减时刻设为 1 分钟后回到主屏等 2~3 分钟（不动应用）→ 跨过时刻后总分自动扣减、历史出现「业力衰减」记录、每日必做 vis 重置。
4. 自证/计时途中跨过衰减时刻：照常扣分，自证跌破起点 → 失败弹窗；计时停止结算分数正确。
